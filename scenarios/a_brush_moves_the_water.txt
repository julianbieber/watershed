# Paint a ridge across a solved document from outside the process, and watch the water go
# round it.
#
# Run with:  just drive run scenarios/a_brush_moves_the_water.txt
#
# What makes this reproducible is that every command holds its reply until its effect has
# landed. `new` answers when the bake has, `solve-water` when the solve has, and `stroke`
# when the rectangle the paint made stale has been re-baked — not when the raster changed.
# Nothing below counts frames.

observe log

fixed-delta 1/60

new 256 256 7 continents
wait bake
zoom fit

# The brush paints into the topmost enabled paint layer of the field on screen, so there has
# to be one before there is anywhere for a stroke to go. Adding it changes nothing on its
# own: a paint layer starts with an empty raster, and an empty raster reads as zero
# everywhere, so the field below is the preset's untouched.
layer add height paint
observe layers
observe brush

brush mode add radius 10 falloff 0.4 strength 0.9 value 1
observe brush

# The baseline, taken after the layer is added rather than before it: adding a layer is a
# structural edit, and an edit invalidates the water it was solved against. Solving first
# would only mean solving twice.
solve-water
wait water
observe water
observe document
observe field

# The assertion this scenario exists for: a ridge laid across the middle of a drained
# landscape dams what used to run through it, so the water above it has to pond where it did
# not before — more lakes, and more standing water. The claim is the count from `observe
# water`, not the PNG, because a picture needs a person to read it.
stroke 16,128 64,120 128,132 192,122 240,130
observe field

# And the claim this line exists to make: `baked` has to still read `whole`. A stroke
# re-bakes the ground it moved rather than dropping the document's extent, which is what
# keeps a painted document solvable without a whole-document bake first.
observe document
capture /tmp/watershed-scenario/painted-ridge.png

solve-water
observe water

# The other half of the assertion: cutting the same line back out has to take the water back
# towards the baseline above. If it did not, the stroke moved something other than the height
# it painted — and a scenario that only ever added would not be able to tell.
brush mode sub
stroke 16,128 64,120 128,132 192,122 240,130
observe document

solve-water
observe water
capture /tmp/watershed-scenario/cut-ridge.png

# Moisture has no paint layer, so `observe brush` has to report no target at all. Inventing
# one would put a layer in the document that nobody asked for, and would do it on the first
# frame of a drag that was aimed at the wrong field.
field moisture
observe brush

observe log
