# Change a field's graph from outside the process, take the changes back one at a time,
# and replay them — from `observe field` and `observe nodes` rather than from a person
# pressing Ctrl+Z and looking.
#
# Run with:  just drive run scenarios/undo_returns_the_graph.txt
#
# What makes this reproducible is that `undo` and `redo` hold their reply exactly as an
# edit does: until the re-bake the change provoked has landed. Nothing below counts
# frames.

observe log

fixed-delta 1/60

new 256 256 7 continents
wait bake
zoom fit

# The graph and the field as the preset built them: the "before" every undo below has
# to get back to. `continents` builds height as one node, n0, a `continents.wgsl` shader.
observe nodes
observe field
observe document

# The three edits the task is named for: add a node, connect it, set a parameter. The
# connect and the set move the field, and the history now reaches three changes back.
# Adopting the stock shader is not an edit of the document and takes no undo step.
shader adopt mountains.wgsl
node add height shader mountains.wgsl
node connect height n0 n1 0
set height.n1.ridge 1.2
observe field
observe document

# Three undos: after each the reply carries what can still be undone, and the field has
# re-baked. At the end the nodes and the quantiles must match the first two observations
# exactly.
undo
observe field
undo
undo
observe nodes
observe field
observe document

# Redo replays every one of them: the field is what it was after the edits.
redo
redo
redo
observe nodes
observe field
observe document

# A move reaches no bake, so taking it back must leave `baked` exactly where it was —
# whole after the redo's re-bake, not nothing.
node place height n1 100 100
undo
observe document

# Everything back to the preset, and the last reply says so: nothing left to undo. One
# more would be refused, which is what `undo` answers with an empty history and what the
# unit tests pin.
undo
undo
undo
observe document
