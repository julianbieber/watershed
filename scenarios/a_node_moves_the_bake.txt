# Edit a field's graph from outside the process and watch the bake follow it.
#
# Run with:  just drive run scenarios/a_node_moves_the_bake.txt
#
# What makes this reproducible is that an edit holds its reply until the re-bake it
# provoked has landed — `node` and `set` answer when the document is settled, not when the
# graph changed. Nothing below counts frames.

# Before anything else: did the run complain? A shader that failed to compile draws nothing
# rather than drawing wrong. `observe log` drains, so this must come before any other call
# to it or the startup errors are already gone.
observe log

fixed-delta 1/60

# 256 square, and fitted — so the visible rectangle a live re-bake covers is the whole
# document, which is what lets `observe field` below be a statement about all of it rather
# than about the part that happened to be on screen.
new 256 256 7 continents
wait bake
zoom fit

# The graph as the preset built it, and the field it bakes. Both are the "before" the rest
# of this scenario is measured against. `continents` builds height as n0 continent noise,
# n1 relief noise, n2 a scale on n1, and n3 the sum it reads from.
observe nodes
observe field

# A node added on its own changes nothing, which is the first thing a graph has to be able
# to say that a stack could not: nothing reaches it, so it is evaluated never and allocates
# nothing. The field below has to be identical to the one above.
node add height constant 0.25
observe field

# Wiring it in is the edit that moves the bake. A constant summed onto the output raises
# every cell, so the quantiles must all rise — and `baked` must have fallen from `whole` to
# `rect`, because a live re-bake covers what is on screen and says so.
node add height binary add
node connect height n3 n5 0

# Wiring the output into a node nothing reads carries the output onto it, from the socket
# exactly as from a wire dragged on the canvas — so `output` has to read n5 here, before any
# `node output` names it.
observe nodes

node connect height n4 n5 1
node output height n5
observe field
observe document

# A node's parameters, one at a time, without rewriting the op around them.
set height.n4.value 0.4
set height.n5.mode mul
observe field
set height.n5.mode add

# Bypassing passes the first input straight through, so the field has to come back exactly
# to where it was before n5 was wired in — that is what makes bypass data rather than the
# caller keeping a copy of the graph.
node bypass height n5 on
observe field

node bypass height n5 off
capture /tmp/watershed-scenario/node-added.png

# A name is an address: once a node has one, every path that named it by id names it by
# name too, and both reach the same node.
node name height n5 total
set height.total.mode max
observe nodes
observe field
set height.total.mode add

# Unwiring rather than deleting. Pointing the output back at n3 leaves n4 and n5 in the
# document but out of the walk, so the field returns to the numbers at the top of this run
# and the two nodes cost nothing while they sit there.
node output height n3
observe field

# And removing them leaves the graph the preset built.
node rm height n5
node rm height n4
observe nodes
observe field

# The other half of what a graph can be told: a value that applies only where moisture is
# high. This is what a masked layer was — a Lerp from what is under it towards what is
# over it, by a weight read from another field through a Remap.
node add height noise ridged 0.01 4 99
node add height scale 0.3
node connect height n6 n7 0
node add height fieldref moisture
node add height remap 0.5 0.8 0 1
node connect height n8 n9 0
node add height binary add
node connect height n3 n10 0
node connect height n7 n10 1
node add height lerp
node connect height n3 n11 0
node connect height n10 n11 1
node connect height n9 n11 2
node output height n11
observe nodes
observe field
capture /tmp/watershed-scenario/weighted-node.png

# The edge that would make the graph feed itself is deliberately not tried here: a
# scenario stops at its first refusal, and that one is expected. It is pinned instead by
# `an_edge_that_would_close_a_cycle_is_refused` in `edit.rs`, where the refusal can be
# asserted rather than ending the run.

# Dragging a card and naming a node are document edits that reach no bake, so neither may
# re-bake anything: `baked` has to be what it was before these two lines.
node place height n11 240 120
node name height n11 weighted
observe document

# A field property rather than a node's. A shift changes the raster the field is written
# onto, so it is the one edit that discards the bake rather than patching it.
set moisture.shift 3
observe nodes

# Water is refused while the document is only part baked, because a drainage network solved
# against a stale height is wrong everywhere the height moved. `bake` is what answers that,
# and it is the whole document rather than the view.
bake
observe document
solve-water
wait water
observe water

# Solve, edit, solve again. This is the sequence that was reported broken from the running
# editor: an edit invalidates the water it produced, and used to take the water *spec* with
# it — so the first edit after the first solve left a document that looked entirely ordinary
# and could never be solved again. Both solves below have to answer with water, and with
# *different* lake counts, since the height under them moved.
#
# Note there is no `bake` here and none is needed: a solve bakes the whole document first
# when it has to, which is what the button does and therefore what this verb does.
set height.n1.op.scale 0.05
solve-water
observe water

set height.n2.factor 0.4
solve-water
observe water

# Close up on one corner. The re-bake covers the visible rectangle, so panning somewhere
# that has not been baked since the last edit has to bring it up to date on its own.
pan 64 64
zoom 96
observe view
observe document
capture /tmp/watershed-scenario/corner.png

# And again at the end, for anything the editing, baking and capturing provoked.
observe log
