# Build a layer from outside the process: add it, remove it, add it again, and carry it
# through a save and a load — from `observe document` and `observe layer` rather than
# from a person typing a name into the panel and looking.
#
# Run with:  just drive run scenarios/a_layer_is_added_from_the_socket.txt
#
# What makes this reproducible is that every verb below holds its reply until the
# document has settled, so nothing here counts frames. The refusals that go with an add
# and a removal — a name already taken, a blank one, one that cannot be a file stem, a
# layer another file reads — are not in this file: replay stops at the first failure,
# so they are pinned by the unit tests in `edit.rs` and `document.rs` instead.

observe log

fixed-delta 1/60

# 256 square and fitted. `continents` builds `moisture` and `height`.
new 256 256 7 continents
wait bake
zoom fit

# The "before" the rest of this is measured against: two layers, `height` on screen,
# and the bake whole.
observe document

# The add itself. The layer list grows by one and the new layer is on screen. It copies
# the template into `shaders/biomes.wgsl`, which is a file operation, so the history
# does not grow.
layer add biomes
observe document

# It came in as the template: its parameters are the template's defaults.
observe layer

# The add takes no undo step, so the way back is a removal, which deletes the file.
layer rm biomes
observe document

# And adding it again writes the template again.
layer add biomes
observe document

# A round trip through the terrain directory. Saving carries the shader directory with
# it, so the layer comes back from its file.
save /tmp/watershed-scenario/added-layer
load /tmp/watershed-scenario/added-layer
observe document
layer biomes
observe layer

# And again at the end, for anything the saving and loading provoked.
observe log
